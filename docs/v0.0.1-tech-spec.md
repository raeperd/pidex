# Pidex v0.0.1: Desktop Pi workflow

Implementation target, not implemented. Supersedes the older
[v1 product reference](prd.md) for this milestone.

## Problem statement

Pidex needs a usable Pi desktop client with clear module ownership and reproducible
use-case tests. The repository currently contains only a skeleton.

## Solution

Launch Electron on macOS, choose one project, and use one Pi conversation. Show
streamed Markdown, collapsible tool inputs/results, model name, and status. Pi
owns history; closing the window keeps work running.

## User stories

1. As a developer, I want to use my Pi credentials and default model, so I can
   start without configuring another agent.
2. As a developer, I want to follow and stop work, so I can change direction
   without losing the conversation.
3. As a developer, I want to reopen the window or recover from a crash, so I can
   return without repeating commands.
4. As a maintainer, I want repeatable user scenarios, so I can diagnose failures.

## Implementation decisions

| Module                        | Owns                                                                                            |
| ----------------------------- | ----------------------------------------------------------------------------------------------- |
| Desktop                       | Windows, folder picker, backend child lifetime, connection credentials, current session locator |
| Contracts                     | Browser-safe Effect Schema and Effect RPC definitions                                           |
| Backend                       | Session/run ownership, prompt acceptance, cancellation, snapshots and subscriptions             |
| Pi integration inside backend | SDK setup, persistence, events and cleanup                                                      |
| Web                           | Rendering, drafts and connection status                                                         |

- **Transport:** Electron owns a loopback HTTP/WebSocket backend child. Use Effect
  RPC + Schema, Effect backend logic, and ordinary Svelte UI code. Web imports
  shared contracts, never backend code. Require a per-launch credential and
  approved origins; preload exposes narrow native capabilities. Keep composition
  at process entry points.
- **Pi:** Pin the latest stable SDK at implementation. Reuse credentials, default
  model resolution, stock tools, retry, compaction, and project instructions.
  Disable external extensions, skills, templates, themes, custom system prompts,
  and package resource loading without modifying user configuration.
- **History:** Pi JSONL files are authoritative; no pidex database. Electron retains
  the exact session locator for backend recovery. Unfinished output may be absent;
  the first turn may have no saved file. Cancellation does not undo file changes.
- **Contract:** Send atomically accepts nonempty input while idle. Stop targets a
  run and waits for cancellation. Watch sends a snapshot then ordered updates
  without a gap. Backend-owned runs survive client disconnects. Never automatically
  resend prompts; reconnect reconciles state and exposes uncertain acceptance.
- **State:** Idle → running → stopping/idle. Failures return to idle with an
  actionable typed error. Busy/disconnected UI keeps drafts editable but disables
  Send; the backend independently rejects busy submissions. Credentials never
  reach the renderer or logs. Keep the project fixed until app exit.

## Testing decisions

Test user workflows primarily through the real backend RPC interface, with real
transport, temporary projects/session files, and controlled model responses.
Exercise real Pi integration where practical. Synchronize explicitly and clean up
resources; automated tests must not touch personal credentials/history.

Each case needs starting conditions, actions, expected results, and an exact
reproduction command. Use its ID in test names and bug reports.

| Case  | Action → expected result                                                                                                     | Verification                   |
| ----- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| UC-01 | Cancel picker, then select project → usable picker, fresh session, displayed model                                           | Electron smoke                 |
| UC-02 | Send → ordered text/tool activity, one completed run, idle                                                                   | API + real Pi                  |
| UC-03 | Send while busy → typed rejection, original run unaffected, editable draft                                                   | API + UI checklist             |
| UC-04 | Stop repeatedly, then send again → wait for cancellation, preserve partial output/history, stale Stop cannot affect next run | API + UI checklist             |
| UC-05 | Disconnect before send acknowledgment, reconnect → run continues, snapshot restored, no duplicate execution                  | API                            |
| UC-06 | Close/reopen window during work → same live session and current output                                                       | Native checklist               |
| UC-07 | Crash backend, manually Restart → exact saved session restored, interruption reported, no automatic continuation             | Process/API + native checklist |
| UC-08 | Recover missing/unreadable session file → explain fresh start/error respectively; never overwrite unreadable history         | Recovery integration           |
| UC-09 | Cancel busy Quit, then confirm → continue first; confirmation cancels and exits without an owned backend left running        | Native checklist               |
| UC-10 | Missing credentials/model or exhausted provider retries → actionable error, no stuck busy state                              | API + UI checklist             |
| UC-11 | Load project instructions and excluded resources → instructions honored, customization excluded, stock tools available       | Pi integration                 |
| UC-12 | Connect without credentials or from unapproved origin → rejected before Pi work                                              | API                            |
| UC-13 | Quit/relaunch → new project selection/session; previous history unchanged                                                    | Native checklist               |

**Done:** CI passes lint, deterministic tests, and build. Formatting/types pass.
macOS passes the Electron launch/connect smoke test and native checklists. Record
an explicit real-Pi run covering file creation/reading, Stop, and window reopening
in a disposable project. No paid requests in CI.

Implementation must supply launch, per-case rerun, and desktop-smoke commands;
fixture setup; backend-crash reproduction; and log locations. Remove the empty-test
exemption when tests exist. Bug reports include case ID, versions, steps,
expected/actual results, and redacted logs. Fixes add regression scenarios.

## Out of scope

- Installers/signing, Windows/Linux desktop acceptance, and remote access.
- History/project lists, project switching, last-session restore after full app
  exit, multiple sessions, automatic backend restart, and independent daemons.
- Model/thinking controls, login UI, external customization, steering/queues,
  dedicated thinking/token/compaction displays, and full automated desktop coverage.
