6. http-error-status-double-table STRONG CORRECTED

plan: http-error-status-double-table.md

Problem. An API error's status is declared twice — at the throw site in HttpError.make({ status: 403, code: "workspace_forbidden" }), and again in the errorStatusMap handed to RPCHandler. 21 of the map's 23 rows restate a throw-site status. ActionProtocolError even declares readonly status = 409 that nothing reads.

Correction — the fix inverts. The first pass proposed making the status travel with the error. But the lockfile pins oRPC 2.0.0-beta.21, and in v2 status was removed from ORPCError; status is resolved by the handler via errorStatusMap. So the sanctioned fix is to stop hand-writing the map: one exported table in errors.ts that both the throw sites and the map read. (Also: docs/architecture.md:64 still says "oRPC 1" — stale.)
Gotcha found while verifying. bad_host is thrown with two statuses — 400 for a missing/malformed Host header, 403 for a disallowed host. Status is not a function of code across the whole server, only across the codes that cross oRPC. The five raw-Node-only codes (bad_host, bad_origin, cross_site, not_found, web_build_missing) stay outside the table.

Deletion test: concentrates cleanly. The fact already exists at each throw site; today it is merely duplicated. Leverage: a new endpoint error goes from 2–3 edits in 2–3 files to one.

8. transcript-follow-ownership-inversion STRONG CORRECTED

plan: transcript-follow-ownership-inversion.md

Problem. Autoscroll is pushed from the data layer: four sites in AppShell must remember to poke the view, and two overlap (the rAF delta flush schedules a scroll, then applyEvent calls it again for every event). A missed fifth site is a silent regression with no type or test to catch it.

Correction. The first pass proposed collapsing nearBottom and following into one state. That would change behaviour: an upward wheel while still inside the 96px threshold detaches autoscroll (by direction) but correctly leaves "Jump to latest" hidden. Preserve the asymmetry — store scroll position, make nearBottom a $derived, keep following the only stored boolean.
Trap found while verifying. prependEarlierMessages grows scrollHeight from the top, then restores position. A naive ResizeObserver sees that growth and yanks a following user to the bottom — the opposite of what loading earlier messages should do. Suppress the observer across the prepend.

Deletion test: concentrates, partially relocates. Controller, attach dance, and four poke sites delete outright; what relocates lands next to resolveFollowing, where a reader already goes for scrolling.
